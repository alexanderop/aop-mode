Two different questions

Suppose an agent must repair a function. It edits a file and finishes without a process error. That tells us the command completed. It does not tell us whether the function now returns the right value.

aop-mode keeps execution checks and outcome checks separate. The runner manages the attempt. Independent checks examine what the agent produced.

TypeScript / illustrative logic 
const executionOk = process.exitCode === 0;
const outcomeOk = checkResult(candidate);

// Finishing is necessary. Correctness needs its own check.
const passed = executionOk && outcomeOk;

This small example explains the distinction. It is not the runner's full implementation.

Where the checks live

The agent works in a fresh candidate workspace. Logs and grading logic stay outside that workspace. This separates the work being examined from the checks used to assess it.

Before a live run, each task's grader must reject a known broken fixture and accept its reference solution. A check that accepts both cannot distinguish a repair from the original defect.

Try the distinction

Keep execution successful and change only the task result. The two attempts finish in the same way, but only one meets the requirement.

What counts as evidence

Workflow evaluations ask additional questions: did the agent read the skill, follow the required procedure, and verify its work? A correct final answer alone cannot establish that those steps happened.

Missing evidence remains missing. Reports distinguish failures, blocked execution, and incomplete evidence instead of turning them into a passing result.
